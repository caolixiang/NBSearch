# Grok 思考区基线文档（Phase 0）

## 目标

为 `plan2.md` 的 Phase 1-7 提供统一验收基线，避免“看起来差不多”的主观判断。

## 基线来源

- 离线站点快照：`/Users/caolixiang/Desktop/grok.com`
- 抓包日志：`log4.txt`、`log5.txt`
- 用户提供截图（思考中、思考结果、正文+思考过程、结果展开）

## 结构基线（截图对齐）

1. 思考中紧凑头部
- 结构：`Grok 黑底 logo` + `chevron` + `黑底图标代理人栈` + `文案(思考过程 · <秒数>)`
- 代理人栈第一屏可见约 4 个，重叠排列。
- 图标顺序观感：`grok / waveform / pen / media(play)`。

2. 思考结果头部（收起后可展开）
- 结构：`彩色像素代理人栈` + `文案(代理人思维方式 · <秒数>)`。
- 不应使用黑底工具图标替代代理人身份头像。

3. 列表区（展开）
- 每行左侧为搜索状态图标（搜索网页 / 搜索图像）。
- 中间为查询语句（需要可读文本，不接受 `%E5%8D%8E...` 这种编码串）。
- 右侧为结果数（例：`15 结果`），按条目稳定显示。

4. 正文结合
- 思考过程区在正文上方，结束后默认收起但可展开查看完整记录。
- 不能出现“面板消失导致历史不可回看”。

## 交互基线（行为）

1. 流式稳定性
- 思考区容器高度稳定，不可出现“突然出现/突然消失”的闪烁。
- 仅内容滚动刷新，不做整块卸载再挂载。

2. 滚动策略
- 思考中：展示最新窗口（滚动刷新）。
- 思考结束：保留完整历史，可展开滚动查看。

3. 收起时机
- 正确时机是思考闭环结束（依据协议状态），不是随机被中间事件反复拉起/收起。

## 协议基线（从 log5 样本确认）

1. 思考状态存在高频切换事件
- `isThinking` 在同一轮会反复出现 true/false。
- 不能直接把每个事件都当作 UI 开关指令，需要状态机去抖和锁定。

2. 图片事件确实已到达前端输入流（不是“上游没传”）
- `cardAttachment.jsonData`（例：`log5.txt:321`）
- `cardAttachmentsJson[]`（例：`log5.txt:2112`）
- 文本中的 `<grok:render card_id="...">`（例：`log5.txt:333`）
- 图搜工具：`tool_name=search_images`（例：`log5.txt:128`、`log5.txt:147`）

3. URL 中文显示问题可复现
- 抓包中存在中文站点 URL 且路径为 percent-encoding（例：`baike.baidu.com/item/%E5%88%98...`，`log5.txt:195`）。
- 展示层应 decode 为中文可读路径，链接跳转保留原始 URL。

## 当前实现与基线差异（本轮确认）

1. 头像体系未分层
- “思考中黑底图标”与“思考结果像素代理人头像”逻辑混用，导致观感错位。

2. 思考区仍有闪烁风险
- 结构化事件与 `<think>` 内容在同轮切换时会抢占渲染模式。

3. 图片链路未完整消费
- 仅靠当前附件解析路径，无法稳定覆盖 `cardAttachment/cardAttachmentsJson + grok:render` 组合。

4. URL 可读性未达标
- 百分号编码未进行展示层 decode。
