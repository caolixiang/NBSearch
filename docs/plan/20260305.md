# 今日目标

- 修复会话续聊在锚点漂移时的可恢复性：命中 `session_anchor_conflict` / `invalid_previous_response_id` 后自动降级重试，避免用户手动重发失败。

## 范围

- In:
  - `streamTurn` 增加锚点冲突错误码识别与单次自动重试。
  - 重试策略仅移除 `previous_response_id`，保留 `session_id`。
  - 补充对应单元测试与回归验证。
- Out:
  - 不改网关协议与错误码定义。
  - 不改会话锚点存储结构。

## Phase 计划

### Phase 81 - 锚点冲突自动降级重试

- 目标：
  - 让网络抖动导致的锚点漂移场景可自动自愈，减少 `session_anchor_conflict` 直出失败。
- 实施项：
  - 在 `streamTurn` 的 `!response.ok` 分支解析网关错误码。
  - 命中 `session_anchor_conflict` / `invalid_previous_response_id` 且请求包含 `previous_response_id` 时，删除该字段并重试一次。
  - 新增单测：首个 400 冲突 + 第二次流式成功，断言第二次请求体不含 `previous_response_id`。
- 验收项：
  - 冲突场景自动重试成功时返回 `completed`，不触发 `failed`。
  - 首次请求带 `previous_response_id`，重试请求不带该字段。
  - `bun run typecheck`、`bun test` 通过。
- 状态：done

### Phase 82 - client_turn_id 幂等与自动恢复闭环

- 目标：
  - 对齐上游新契约：主链以 `session_id + client_turn_id` 为恢复主轴，失败后可自动“查 turn + 补拉 messages + 必要时重发”。
- 实施项：
  - `streamTurn` 请求体新增 `client_turn_id`，并增加 `Idempotency-Key` 请求头。
  - 普通对话默认不常态依赖 `previous_response_id`（仍保留冲突兜底逻辑）。
  - 新增恢复链路：调用 `/v1/sessions/{session_id}/turns/{client_turn_id}`、`/state`、`/messages`，实现 completed 补拉与 not_found 自动重发一次。
  - 补充服务层测试：网络异常后 turn completed 自动恢复、turn not_found 自动重发。
- 验收项：
  - 网络中断场景可自动恢复为 `completed` 或安全重发，不直接进入不可恢复失败。
  - 请求中携带 `client_turn_id` 与 `Idempotency-Key`。
  - `bun run typecheck`、`bun test` 通过。
- 状态：done

### Phase 83 - 重生成改为确认后提交剪裁

- 目标：
  - 重生成失败/中断不再污染本地锚点与消息分支。
- 实施项：
  - 移除重生成开始前的本地 `truncate + anchors 回退`。
  - 改为重生成 `completed` 后再执行“剪裁旧分支 + 提交新 assistant”。
  - 保持失败分支只报错不改锚点。
- 验收项：
  - 重生成失败后，后续普通发送不受本地锚点漂移影响。
  - `bun run typecheck`、`bun test` 通过。
- 状态：done

## Phase 验收记录

### Phase 81

- 验收结果：
  - 服务端返回 `session_anchor_conflict` 时，客户端会自动移除 `previous_response_id` 并在同轮内重试一次。
  - 新增单测 `retries once without previous_response_id on session anchor conflict`，验证两次请求体字段差异及最终完成事件。
  - 既有“idle timeout 重试保留 previous_response_id”测试继续通过，说明新逻辑未影响原重试路径。
- 备注：
  - 当前自动恢复仅重试一次，避免无限重试与重复写入风险。

### Phase 82

- 验收结果：
- 已接入 `client_turn_id` 与 `Idempotency-Key`，并在同一 turn 的自动重试中保持稳定不变。
- 已实现 `/v1/sessions/{session_id}/turns/{client_turn_id}`、`/state`、`/messages` 恢复链路：
  - turn completed：自动补拉并落库，转为 `completed`。
  - turn not_found：自动重发一次原请求（同 `client_turn_id`）。
- 普通主链在已有 `session_id` 时不再常态发送 `previous_response_id`，仅保留“仅锚点场景”兼容。
- 新增服务层回归测试覆盖：`transport failure -> completed recover`、`transport failure -> not_found retry`。
- 备注：
- 该阶段只改服务层与协议消费；重生成“确认后提交剪裁”在 Phase 83 完成。

### Phase 83

- 验收结果：
- 重生成流程已移除“开始前本地截断 + 锚点回退”，失败路径不再写入破坏性状态。
- 已改为 completed 后提交剪裁：先删除目标 assistant 及后续旧分支，再写入新 assistant 并更新 anchors。
- 普通发送与重生成都显式携带 `client_turn_id`，与服务层幂等语义一致。
- 备注：
- 本地提交动作放在 completed 分支执行，保持“确认后提交”的分支安全性。
