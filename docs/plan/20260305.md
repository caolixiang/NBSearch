# 今日目标

- 修复会话续聊在锚点漂移时的可恢复性：命中 `session_anchor_conflict` / `invalid_previous_response_id` 后自动降级重试，避免用户手动重发失败。

## 范围

- In:
  - `streamTurn` 增加锚点冲突错误码识别与单次自动重试。
  - 重试策略仅移除 `previous_response_id`，保留 `session_id`。
  - 补充对应单元测试与回归验证。
- Out:
  - 不改网关协议与错误码定义。
  - 不改会话锚点存储结构。

## Phase 计划

### Phase 81 - 锚点冲突自动降级重试

- 目标：
  - 让网络抖动导致的锚点漂移场景可自动自愈，减少 `session_anchor_conflict` 直出失败。
- 实施项：
  - 在 `streamTurn` 的 `!response.ok` 分支解析网关错误码。
  - 命中 `session_anchor_conflict` / `invalid_previous_response_id` 且请求包含 `previous_response_id` 时，删除该字段并重试一次。
  - 新增单测：首个 400 冲突 + 第二次流式成功，断言第二次请求体不含 `previous_response_id`。
- 验收项：
  - 冲突场景自动重试成功时返回 `completed`，不触发 `failed`。
  - 首次请求带 `previous_response_id`，重试请求不带该字段。
  - `bun run typecheck`、`bun test` 通过。
- 状态：done

## Phase 验收记录

### Phase 81

- 验收结果：
  - 服务端返回 `session_anchor_conflict` 时，客户端会自动移除 `previous_response_id` 并在同轮内重试一次。
  - 新增单测 `retries once without previous_response_id on session anchor conflict`，验证两次请求体字段差异及最终完成事件。
  - 既有“idle timeout 重试保留 previous_response_id”测试继续通过，说明新逻辑未影响原重试路径。
- 备注：
  - 当前自动恢复仅重试一次，避免无限重试与重复写入风险。
