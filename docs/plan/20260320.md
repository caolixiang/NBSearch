# 今日目标

- 扩展订阅系统，新增 Kalshi 来源；同时修复窗口隐藏到 tray 后订阅不再继续同步的问题，并优化订阅交互。

## 范围

- In:
  - 扩展 feed source/config/runtime/service，支持 `polymarket` + `kalshi`
  - 泛化订阅抓取解析、订阅流 UI、设置页与侧边栏入口
  - 修复 tray 后订阅不同步，改为原生侧调度 + 前端执行同步
  - 补充测试并完成构建验证
- Out:
  - 不改现有聊天/语音主链协议
  - 不把 feed 抓取/翻译/入库整体迁到 Rust
  - 不新增新的第三方订阅源（除 Kalshi 外）

## Phase 计划

### Phase 1 - 多源订阅主链

- 目标：把现有单一 `polymarket` 订阅泛化为多来源，并新增 `kalshi`。
- 实施项：
  - 扩展 `FeedSource`、`AppConfig`、Tauri config 命令与 runtime 配置
  - 泛化 Jina 抓取配置与 X 时间线 parser，支持 Polymarket/Kalshi 共用主链
  - 调整 feed service、repository 调用与调研 helper，支持 source metadata，并收口前端 due-check 调度与 native tick listener 接口
- 验收项：
  - Kalshi 可作为独立来源启停、同步、入库、分页与带聊
  - Polymarket 现有行为不回归
- 状态：done

### Phase 2 - UI 与交互优化

- 目标：把订阅入口、设置与内容面板改成双来源可用，并提升交互清晰度。
- 实施项：
  - 设置页订阅区支持两个来源的独立开关与说明
  - 侧边栏显示多个订阅入口
  - 主内容面板泛化为来源驱动，统一状态、按钮与空态文案
- 验收项：
  - 用户能清晰切换 Polymarket/Kalshi
  - 订阅区交互与状态展示比单来源版本更清楚
- 状态：done

### Phase 3 - Tray 后台同步修复

- 目标：修复窗口隐藏到 tray 后前端计时器失效导致的订阅停止同步问题。
- 实施项：
  - 在 Tauri 原生侧增加订阅调度 tick 事件
  - 窗口恢复时补发一次 catch-up tick，让前端已有 due-check 调度立即执行
  - 设置保存时同步更新运行时订阅配置
- 验收项：
  - 隐藏到 tray 后仍可继续触发订阅同步
  - 恢复窗口时能立即刷新遗漏状态
- 状态：done

### Phase 4 - 测试与验证

- 目标：补齐多源订阅与 tray 调度相关回归测试并完成编译验证。
- 实施项：
  - 更新/新增 parser、service、config、UI helper 测试
  - 执行 `bun test`、`bun run typecheck`、`bun run build`、`cargo check`
