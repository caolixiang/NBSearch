# 今日目标

- 支持“对话 A 生成中时，用户可切换到对话 B 浏览/操作，再切回 A 继续看到实时进度”。
- 不中断后台已发起的流式请求，不丢失中间状态。

## 范围

- In:
  - 将单实例流式状态改为会话级状态管理。
  - 明确切换会话时的状态保留与并发规则。
  - 保持现有 repository + 本地 DB 持久化链路不变。
- Out:
  - 本阶段不引入 `react-query`。
  - 不做 e2e 测试体系建设。

## Phase 计划

### Phase 1 - 会话级流式状态改造方案确认

- 目标：
  - 完成可执行方案定义，覆盖状态模型、切换行为、并发约束、验收口径。
- 实施项：
  - 状态管理：引入会话级 Store（建议 `zustand`），按 `conversationId` 维护状态。
  - 会话状态字段：`isStreaming`、`assistantDelta`、`reasoningEvents`、`startedAt`、`abortController`、`lastError`。
  - 会话切换：仅变更 `activeConversationId`，不清理其他会话的流式状态。
  - 并发约束：同会话禁止并发两条流；不同会话允许并行流任务。
  - 数据链路：继续使用 repository + 本地 DB 持久化路径。
- 验收项：
  - A 会话生成中可切到 B，会话列表与消息可正常操作。
  - 切回 A 后继续看到 A 的实时流式进度。
  - A 完成后消息正确入库，刷新后内容一致。
  - B 不受 A 流状态污染（不出现串流、错位展示）。
- 状态：done

### Phase 2 - 会话切换不中断流式（第一批实现）

- 目标：
  - 先解除“生成中无法切换会话”的阻塞，并保证切回原会话时可继续看到实时流式内容。
- 实施项：
  - 将消息缓存改为按 `conversationId` 存储（`messagesByConversationId`）。
  - 将推理事件映射改为按 `conversationId` + `messageId/responseId` 双层存储。
  - 新增会话级流式状态映射 `streamingStateByConversationId`，流式渲染按当前会话读取，避免跨会话串流显示。
  - 切换会话时不再重置流式状态；若目标会话正在流式，保留本地流式视图，不强制 reload 覆盖。
  - 会话删除时清理对应会话缓存映射（消息、推理、错误）。
- 验收项：
  - 流式进行中可切到其他会话并浏览历史消息。
  - 切回原会话可继续看到正在流式输出的内容。
  - 历史会话与当前流式会话不再出现 UI 串流展示。
- 状态：done

### Phase 13 - 心跳/超时失败/基础续流语义

- 目标：
  - 提升长流稳定性与可观测性，补齐心跳与超时错误语义。
- 实施项：
  - 新增 `heartbeat` 事件（携带 `meta`），按固定间隔从流读取侧发出。
  - 为 `reader.read()` 增加空闲超时保护，超时时发出明确失败码（如 `stream_idle_timeout`）。
  - 在会话侧记录最近心跳时间，用于后续可视化与续流扩展（本阶段不改上游协议）。
- 验收项：
  - 网络卡住时不再无限等待，可收到明确失败事件。
  - 长流过程中可观测到心跳事件。
- 状态：done

### Phase 14 - 断线重连与基础续流恢复（meta/responseId）

- 目标：
  - 在流式空窗期触发超时时，进行一次无感重连，减少“刚开始就失败”的体验断点。
  - 请求链路显式传递 `previous_response_id`，增强续流上下文一致性。
- 实施项：
  - `streamTurn` 新增“空窗期超时一次重试”策略：仅在尚未收到可解析流事件时生效，避免中途重复内容。
  - 重试期间保留同一请求上下文，不重复入库用户消息。
  - 请求体新增 `previous_response_id`（来自 `anchors.lastResponseId`），并在重连时沿用。
  - 增补单测覆盖：首轮超时后重连成功、请求体包含 `previous_response_id`。
- 验收项：
  - 空窗期网络抖动时，可自动重连继续流式。
  - 非空窗期超时仍返回明确失败码，不进入重复输出风险路径。
- 状态：done

### Phase 15 - 连接健康状态可视化

  - 对 `stream_idle_timeout` 提示文案做用户可读化（避免暴露内部错误串）。
- 验收项：
  - 生成过程中可实时看到连接状态变化。
  - 超时失败时错误提示清晰可读。
