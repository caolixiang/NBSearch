# 今日目标

- 为桌面端增加基于 Jina 的 Polymarket 订阅能力，支持本地持久化、启动补抓、10 分钟轮询与历史分页浏览。

## 范围

- In:
  - 新增本地订阅 schema 与 repository 接口
  - 新增 Jina 抓取、Markdown 解析、去重与轮询服务
  - 启动时自动补抓，运行中每 10 分钟轮询
  - 新增设置开关、订阅列表与“加载更多”
  - 补充单元测试与构建验证
- Out:
  - 不接入现有 Grok HTTP 网关
  - 不保证应用彻底退出期间的完整历史补齐
  - 不实现多账号、多来源订阅
  - 不自动把订阅内容注入聊天上下文

### Phase 5 - OpenAI 翻译配置与翻译链路接入

- 目标：新增独立的 OpenAI-compatible 翻译配置，并将 Polymarket 入库前中文翻译接入 AI SDK。
- 实施项：
  - 扩展 `config.toml`、Tauri commands、`AppConfig` 与 runtime，新增独立 `llm` 配置段
  - 引入 AI SDK + OpenAI-compatible provider，使用单独的 `base_url/api_key/model`
  - 扩展 `feed_items` schema 与 repository，持久化中文翻译及翻译状态
  - 在 Polymarket 同步链路中对新增条目做入库前翻译，失败时保留原文兜底
  - 设置页新增独立翻译配置区
- 验收项：
  - 不影响现有 Grok 聊天/语音网关配置
  - 新增 feed item 可持久化原文 + 中文翻译
  - 未配置 LLM key 时不会阻断订阅主链
- 状态：done

### Phase 7 - 翻译回填与 OpenAI 联通测试

- 目标：让翻译失败/跳过的 feed item 在后续同步时自动回填，并为独立 OpenAI 配置提供真实联通测试。
- 实施项：
  - 扩展 repository 与 feed service，支持查询/更新待补翻译条目
  - 在同步链路中补一轮旧条目翻译回填，避免失败后永久停留原文
  - 将设置页 `LLM 网关` 调整为独立 `OpenAI` 区
  - 默认翻译模型调整为 `gpt-5.4-mini`
  - 新增 `联通测试` 按钮，使用配置的 OpenAI-compatible 网关发送 `hello`
- 验收项：
  - 历史 `failed/skipped` 条目可在后续同步中自动补翻
