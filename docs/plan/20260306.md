# 今日目标

- 完成会话链路“所有重试契约”配置化，并增强“仅用户消息未获助手结果”场景的恢复健壮性（自动恢复 + 单按钮重试）。

## 范围

- In:
  - 服务层恢复结果新增 `in_progress` 分支。
  - `turn in_progress` 时基于 `session state` 校验活跃 turn 后执行有限次重试。
  - 超出重试预算时返回明确失败码 `turn_in_progress`。
  - 新增对应单元测试覆盖“可恢复成功”和“超限失败”。
  - 从 `config.toml` 读取 `turn_in_progress` 重试参数并透传到服务层。
  - 扩展为“所有重试契约”配置化：`stream idle`、`not_found` 重发、`in_progress` 轮询与重试、恢复消息 limit。
  - 增加 pending 轮次自动恢复与单按钮重试（仅 `重试`）。
- Out:
  - 不改网关接口与协议字段。
  - 不改前端展示逻辑与文案映射。

## Phase 计划

### Phase 85 - in_progress 长尾恢复与失败语义收口

- 目标：
  - 当网关返回 `session_in_progress/turn_in_progress` 且 turn 仍在执行时，客户端可继续恢复，不立即失败。
- 实施项：
  - `TurnRecoveryOutcome` 增加 `in_progress`。
  - `attemptTurnRecovery` 在 turn 持续 `in_progress` 时查询 `/state`，确认活跃 turn 一致后返回 `in_progress`。
  - `streamTurn` 在 `in_progress` 下等待后重试同请求（同 `client_turn_id`）；超出预算后 `emitFailed("turn_in_progress")`。
  - 新增测试：
    - `in_progress -> retry -> completed`
    - `in_progress` 持续超时 -> `turn_in_progress`
- 验收项：
  - recover 成功路径不触发 failed。
  - recover 超限路径输出 `turn_in_progress`。
  - `bun run typecheck`、`bun test` 通过。
- 状态：done

### Phase 86 - 恢复参数配置化（仅 config.toml）

- 目标：
  - 在不增加用户设置认知成本的前提下，将 `turn in_progress` 的重试预算/等待时长配置化。
- 实施项：
  - 扩展 `read_gateway_config` 返回字段：`turnInProgressRetryMaxAttempts`、`turnInProgressRetryDelayMs`。
  - 扩展前端 `AppConfig` 与 `loadAppConfig`：读取上述字段并保持 `config.toml > .env` 优先级。
  - `GrokChatService` 改为优先使用配置值，缺省回退默认值（1 次，600ms）。
  - 更新服务层测试：覆盖“配置为 0 次重试时立即返回 turn_in_progress”。
- 验收项：
  - 未配置时行为与之前一致。
  - 手工配置可生效且无需 UI 入口。
  - `bun run typecheck`、`bun test` 通过。
- 状态：done

### Phase 87 - 首次保存网关时写入恢复默认值

- 目标：
  - 保持“默认不自动落盘”的前提下，在用户首次保存网关配置时，把 recovery 默认参数同步写入 `config.toml`。
- 实施项：
  - 在 `save_gateway_config` 中规范化 recovery 参数后写回 `parsed.recovery`。
  - 保持返回 payload 与落盘值一致。
- 验收项：
  - 新用户首次保存网关后，`config.toml` 包含 `recovery.turn_in_progress_retry_max_attempts` 与 `recovery.turn_in_progress_retry_delay_ms`。
  - `bun run typecheck`、`bun test`、`cargo check --manifest-path src-tauri/Cargo.toml` 通过。
- 状态：done

### Phase 88 - 全量重试契约配置化

- 目标：
  - 将 `GrokChatService` 中剩余重试/轮询/超时参数全部纳入 `config.toml` 的 `recovery`，并在首次保存网关时统一落盘默认值。
- 实施项：
  - 扩展 Tauri `GatewayConfigTomlSection/ GatewayConfigPayload`：新增 `stream_idle_*`、`turn_recovery_*` 字段。
  - 扩展前端 `AppConfig/loadAppConfig`：读取新增字段并保持 `config.toml > .env`。
  - 服务层改为读取配置字段：
    - `streamIdleTimeoutMs`
    - `streamIdleRetryMaxAttempts`
    - `streamIdleRetryDelayMs`
    - `turnRecoveryMessagesLimit`
    - `turnRecoveryNotFoundRetryMaxAttempts`
    - `turnRecoveryPollInProgressMaxAttempts`
    - `turnRecoveryPollInProgressDelayMs`
    - `turnInProgressRetryMaxAttempts`
    - `turnInProgressRetryDelayMs`
  - 新增测试：`streamIdleRetryMaxAttempts=0` 时不重试 idle timeout。
- 验收项：
  - 所有重试契约参数均可从 `config.toml.recovery` 生效。
  - 首次保存网关后 `recovery` 默认字段完整落盘。
  - `bun run typecheck`、`bun test`、`cargo check --manifest-path src-tauri/Cargo.toml` 通过。
- 状态：done

### Phase 89 - pending 轮次恢复与单按钮重试

- 目标：
  - 处理“只有用户消息、无助手结果”场景，确保可自动恢复，且仅暴露一个 `重试` 按钮。
- 实施项：
  - 服务层新增 `recoverPendingAssistant`：按 `session_id + last_response_id` 从 `/sessions/{id}/messages` 补拉最新 assistant 并落库。
  - `streamTurn` 新增 `retryExistingUserMessage` 语义：重试既有用户轮次时不重复入库 user 消息。
  - UI 增加 pending 检测（末条为 user）与启动后自动恢复尝试。
  - 头部仅新增一个 `重试` 按钮；点击优先补拉恢复，补拉失败再重发同一用户文本（附件场景提示重新上传）。
  - 新增测试：`recoverPendingAssistant` 成功补拉；`streamIdleRetryMaxAttempts=0` 不重试。
- 验收项：
  - 退出应用/手动中止后，不会长期停留“只有用户消息”且无恢复入口。
  - 同一用户轮次重试不产生重复 user 消息。
  - `bun run typecheck`、`bun test`、`cargo check --manifest-path src-tauri/Cargo.toml` 通过。
- 状态：done
